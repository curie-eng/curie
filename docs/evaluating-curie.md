# Evaluating Curie: a technical guide

Checked against release v0.14.3 and main at d413717fc90c5655fce2e89194bc219f7b5499d4

This page indexes the maintained sources; it is not a second architecture reference. Each claim links its canonical detail, and each section separates what the release ships, what is unreleased on main, and what is design only (an Accepted ADR not yet realized in code). Status words are Released, Released with limits, Unavailable, and Unreleased, defined in the [capability reference](capabilities.md#reading-the-status). When a canonical source and the code disagree, this page states what the code does and names #3844, which owns the canonical corrections.

## Components and deployment topology

The static [component map](../ARCHITECTURE.md#component-map) shows who talks to whom; the [message-flow](diagrams/message-flow.md), [Kubernetes](diagrams/kubernetes.md), and [ACI](diagrams/aci.md) diagrams show the running paths. Curie builds six things around an adopted spine: the web UI, the API server, the Slack dispatcher, the worker plus runner glue, the CLI, and the umbrella Helm chart. Adopted systems are Langfuse, the Kubernetes Agent Sandbox, Slack Bolt, AgentMail, Valkey Streams, Postgres, the OTel Collector, the claude-agent-sdk harness, and the Claude Code plugin format ([Adopted, not built](../ARCHITECTURE.md#adopted-not-built), [ADR-0007](adr/0007-adopt-not-build-boundaries.md) Accepted).

Two frozen contracts bound every lane: the ACI session protocol under [`packages/aci-protocol`](../packages/aci-protocol) and the Claude Code plugin bundle format under [`packages/plugin-format`](../packages/plugin-format), both CI-gated ([frozen contracts](../ARCHITECTURE.md#frozen-contracts), [ADR-0017](adr/0017-tri-language-contract-codegen.md) Accepted).

Released: the chart brings up Postgres, Valkey, Langfuse, ClickHouse, RustFS, the OTel Collector, and the api, dispatcher, mail-adapter, worker, and ui services; the GHCR-default install is proven end to end on a fresh k3s cluster ([Deployment, CI, and release](../ARCHITECTURE.md#deployment-ci-and-release)). The local stack is [`compose.dev.yaml`](../compose.dev.yaml), and the runner-only `skill` tier has neither the durable state nor the approval plane ([deployment ownership](capabilities.md#deployment-ownership)). Unreleased or deferred on main: usable email ingress, the Interview-Me onboarding compiler, automatic memory generation, and the native OpenAI wire format ([What is built vs deferred](../ARCHITECTURE.md#what-is-built-vs-deferred)).

## One factory issue, end to end

The factory turns a labelled issue into a pull request, on the same stream, sandbox, and approval plane as a Slack turn. The tracker stays the backlog; Curie stores one WorkItem per repository and issue and one bounded ExecutionRequest per attempt ([`apps/api/src/curie_api/models.py::WorkItem`](../apps/api/src/curie_api/models.py), [`apps/api/src/curie_api/models.py::ExecutionRequest`](../apps/api/src/curie_api/models.py)). The full sequence is [One factory run, end to end](../ARCHITECTURE.md#one-factory-run-end-to-end).

1. Intake and admission. The poller is the default ([`apps/api/src/curie_api/factory_poll_intake.py::poll_once`](../apps/api/src/curie_api/factory_poll_intake.py)); the signed webhook is opt-in ([`apps/api/src/curie_api/github_factory.py::handle_factory_delivery`](../apps/api/src/curie_api/github_factory.py)). Both check the installation, allowlist, and sender permission ([`apps/api/src/curie_api/github_factory.py::verify_current`](../apps/api/src/curie_api/github_factory.py)) and resolve the base branch ([`apps/api/src/curie_api/factory_base.py::resolve_base`](../apps/api/src/curie_api/factory_base.py)). Base-resolution refusal posts a comment and writes no WorkItem; earlier intake refusals can return without a comment ([ADR-0161](adr/0161-signed-github-issue-events-admit-one-work-item.md), [ADR-0186](adr/0186-a-factory-ticket-declares-its-base-and-keeps-it.md), [ADR-0187](adr/0187-the-factory-polls-github-and-the-platform-reads-the-issue.md), all Accepted).
2. Records. Admission writes a waiting WorkItem and ExecutionRequest with a wait deadline ([ADR-0145](adr/0145-a-labelled-issue-is-a-backlog-item-and-the-stream-is-its-queue.md) and [ADR-0162](adr/0162-work-items-own-durable-execution-identity.md), Accepted).
3. Capacity wait and execution. The WorkItemReconciler claims the due request under a lease and publishes an execute wake onto `curie:runs`; the worker acquires it, or defers on the same request when no sandbox capacity is free ([`apps/api/src/curie_api/workitem_reconciler.py::WorkItemReconciler`](../apps/api/src/curie_api/workitem_reconciler.py), [ADR-0157](adr/0157-factory-work-dispatches-from-sql-over-the-runs-stream.md) Accepted). A run boots with scoped issue-read and progress capabilities, never a GitHub credential ([`apps/api/src/curie_api/routers/work_item_issue.py::read_work_item_issue`](../apps/api/src/curie_api/routers/work_item_issue.py), [ADR-0174](adr/0174-publication-prechecks-use-an-execution-scoped-capability.md) Accepted). Capacity wait detail and knobs are in [Factory work items wait for capacity](operations.md#factory-work-items-wait-for-capacity).
4. Diff review and verification. A plan review runs once and is advisory; the implement and diff-review loop runs at most five rounds, and the default bundle's review gate hook enforces the loop and the verification contract ([`examples/dark-factory/README.md`](../examples/dark-factory/README.md#review-loops), [`examples/dark-factory/hooks/review_gate.py`](../examples/dark-factory/hooks/review_gate.py)).
5. Publication. The approval and publication are written together, under the per-agent policy of [ADR-0147](adr/0147-publication-approval-is-a-per-agent-operator-policy.md) (Accepted); a worker loop runs a Kubernetes Job that pushes only the branch, then the API proves the commit and finds or opens the pull request ([`apps/api/src/curie_api/crud/publications.py::create_publication`](../apps/api/src/curie_api/crud/publications.py), [`apps/worker/src/curie_worker/publication_loop.py::PublicationReconcileLoop`](../apps/worker/src/curie_worker/publication_loop.py), [`apps/api/src/curie_api/routers/publication_code_host.py`](../apps/api/src/curie_api/routers/publication_code_host.py)).
6. Recorded outcome. The CI gate observes checks on the published head and reruns failed jobs once; the reconciler edits the one status comment and moves labels, and operators read outcomes with states such as waiting, running, published, cancelled, and failed ([`apps/api/src/curie_api/factory_ci.py::gate`](../apps/api/src/curie_api/factory_ci.py), [Reading work item outcomes](operations.md#reading-work-item-outcomes)).

| Configured model provider | Receives prompts and returns model output. The credential is prefix-mapped from a Secret to the SDK environment without any application process brokering it. | [The credential path](../ARCHITECTURE.md#the-credential-path), [ADR-0015](adr/0015-credential-plane.md) (Accepted) |
| Code host and tracker | The pushed branch and pull request, issues, status comments, and labels. The sandbox holds no code-host credential. | [`apps/api/src/curie_api/routers/publication_code_host.py`](../apps/api/src/curie_api/routers/publication_code_host.py), [Forge tracker and code host](interfaces.md) |
| Slack (when connected) | Conversation messages and replies, one OAuth app per workspace, routed by `team_id`. | [Handling a Slack mention](../ARCHITECTURE.md#handling-a-slack-mention-message-flow), [Slack conversations](capabilities.md#workspaces-and-integrations) |

Connector secret values differ by tier: on the local tier they are stored in a nullable `secrets` JSONB column on the agent row, while the cluster tier stores only the names there and delivers values through a per-agent Kubernetes Secret ([`apps/api/src/curie_api/models.py::Agent`](../apps/api/src/curie_api/models.py), [ADR-0009](adr/0009-per-agent-connector-auth.md) Accepted).

Approvals are decided and authorized in the API, which resolves membership from the resolver's credential, never from the request body, and wakes the suspended session with the decision ([docs/approvals.md](approvals.md), [ADR-0034](adr/0034-approval-authorizers-resolve-membership-in-the-api.md) and [ADR-0046](adr/0046-converged-approval-gates-and-durable-provenance.md), Accepted). Publication approval is a separate per-agent operator policy.

One agent's run is isolated from another's by a sandbox per run with scoped capabilities ([ADR-0033](adr/0033-scoped-sandbox-state-token.md) Accepted), by per-agent connector secrets in their own Secret, and by default-deny egress with gVisor and per-run budgets ([Security rails](adr/0006-security-rails-as-chart-defaults.md) Accepted).

Tenant boundary. A single self-host install auto-provisions one default tenant. [ADR-0008](adr/0008-multi-tenancy.md) (Accepted) specifies pooled Postgres with database-forced row-level security and namespace-per-tenant sandboxes. The application-level part is realized: core tables carry a `tenant_id` column and the worker filters agents and bindings by tenant in application code ([`apps/api/alembic/versions/0101_tenant_scope_core.py`](../apps/api/alembic/versions/0101_tenant_scope_core.py), [`apps/worker/src/curie_worker/binding.py`](../apps/worker/src/curie_worker/binding.py)). The database-forced isolation is not: [`apps/api/src/curie_api/db.py`](../apps/api/src/curie_api/db.py) ships one `curie` schema with no row-level security policy, and [`charts/curie/templates/agent-sandbox.yaml`](../charts/curie/templates/agent-sandbox.yaml) renders one release namespace rather than one per tenant. The gap between the ADR and the code is tracked as #3844.

## Persistence, failure and recovery

1. Retry. Delivery is at-least-once over Valkey streams with an idempotent, side-effect-aware kernel and a dead-letter graveyard for bounded delivery ([ADR-0013](adr/0013-concurrency-and-delivery-model.md), [ADR-0039](adr/0039-bounded-delivery-and-a-dead-letter-graveyard.md), Accepted). The CI gate reruns failed GitHub Actions jobs once and never treats unreadable CI as success ([factory settlement](../ARCHITECTURE.md#one-factory-run-end-to-end), [`apps/api/src/curie_api/factory_ci.py::gate`](../apps/api/src/curie_api/factory_ci.py)).
2. Cancellation. Unlabel, close, or relabel of running work, the deadline, or a lost owner moves a request to `cancellation_requested`; a terminate wake tears the sandbox down ([stopping a factory run](../ARCHITECTURE.md#one-factory-run-end-to-end), [`apps/worker/src/curie_worker/workitem_orphans.py::WorkItemOrphanSweeper`](../apps/worker/src/curie_worker/workitem_orphans.py)). A qualifying issue cancellation settles even when no worker teardown receipt arrives within the window, after which a late receipt is refused as stale ([`apps/api/src/curie_api/workitems/lifecycle.py::settle_overdue_cancellation`](../apps/api/src/curie_api/workitems/lifecycle.py)).
3. Lease expiry. A lapsed acquire lease returns the unstarted request to waiting for redispatch, so a dead worker's request re-dispatches within about 75 seconds ([`apps/api/src/curie_api/workitem_dispatch.py::redispatch_lapsed_acquisitions`](../apps/api/src/curie_api/workitem_dispatch.py)); an expired runtime heartbeat is declared `owner_lost` and handed to the terminate chain ([`apps/api/src/curie_api/workitem_dispatch.py::declare_owner_lost`](../apps/api/src/curie_api/workitem_dispatch.py)). Capacity-wait expiry is separate: the waiting deadline from admission, surfacing as `expired` / `capacity_wait_expired` ([Factory work items wait for capacity](operations.md#factory-work-items-wait-for-capacity)).
4. Operator recovery. Operators read outcomes and act on causes through the read-only `GET /work-items` routes ([Reading work item outcomes](operations.md#reading-work-item-outcomes)); the documented upgrade paths cover approvals pending across a worker roll and the schema-upgrade fence that keeps the API up ([Upgrading the chart](operations.md#upgrading-the-chart)).

## Verification evidence

What verifies a Curie claim, and what is recorded rather than asserted. The [live verification status](../ARCHITECTURE.md#what-is-built-vs-deferred) records previously observed Slack and local or cluster loops; validate your own workflow before relying on it. CI runs Python (ruff, mypy, pytest against real services), Rust, the UI, image builds, and the parity ladder, and the chart has its own runtime proofs ([Deployment, CI, and release](../ARCHITECTURE.md#deployment-ci-and-release)). Releases are authorized by their own verification flow ([Verifying a release](release-verification.md)). The interface catalog and ADR index are generated and drift-gated, so every citation resolves ([ADR-0043](adr/0043-generated-interface-catalog-and-doc-lint-gate.md) Accepted). Correctness is never asserted by the platform: every work item reports `correctness: {"asserted": false, "owner": "bundle"}` ([Reading work item outcomes](operations.md#reading-work-item-outcomes)).
