# 227. Opt-in final-answer publication validation

Date: 2026-10-14

Status: Accepted

Superseded in part by [ADR 0250](0250-verbatim-slack-answers-render-as-rich-text-sections-with-literal-links.md): clause 8's Slack rendering sentence ("emits literal plain-text blocks"); verbatim answers now render as rich text sections with literal links. The rest of this ADR stands.

Accepted alongside implementation with explicit maintainer approval from Junwon Jung on 2026-10-14 under ADR 0102. Approval covers the reviewed generic final-answer publication boundary and the realizing paths below. On the same date Junwon Jung also approved scoping the requirement to declared trigger tools, with a per-turn `Final.text_mode` mark so a mixed bundle's ordinary answers keep their rendering.

Tracked in [#4560](https://github.com/curie-eng/curie/issues/4560).

## Context

A bundle can require its own validation tool to check an answer before publication. A prompt asking the model to call that tool does not establish that it ran successfully in this turn, or that the text delivered is the text it approved. Current translation accepts a successful provider result without such a correlation. Runner connector notices and worker receipts can subsequently change that text.

## Decision

1. Extend the Curie-owned `curie.bundle.json` sidecar with an optional `finalAnswer` object: `{"version": 1, "tool": "mcp__answer_checks__finalize_answer"}`. `tool` is an exact SDK-qualified tool name, not a suffix or pattern. An optional `triggers` array of distinct exact SDK-qualified tool names, excluding `tool`, scopes the requirement to a declared workflow: `{"version": 1, "tool": "mcp__answer_checks__finalize_answer", "triggers": ["mcp__deck_review__inspect_deck"]}`. The root and this object remain strict. Absence of `finalAnswer` preserves existing unconstrained behavior. This does not modify the frozen plugin-format or ACI contracts.
2. The configured bundle-owned tool accepts an input object containing a nonempty UTF-8 `draft` string. It returns exactly one JSON object, directly or in a single MCP text content block, with `version: 1`, `draftSha256` (lowercase SHA-256 of the exact UTF-8 draft), and nonempty `text` (the approved publication text). These are required fields; unknown envelope fields are refused. Input and result each have a 64,000-byte UTF-8 JSON limit. Curie establishes correlation and publication integrity; the bundle owns semantic validation and its own tool implementation.
3. Without `triggers`, every turn is constrained. With `triggers`, a turn becomes constrained when it observes a call to any listed tool, top-level or nested; activation then lasts for the rest of that turn, through invalidation, steering and later tool activity, and never carries into another turn. This enforces the declared flow once it starts. It does not detect a request the model answered without calling a listed tool, which publishes as an ordinary answer; a bundle that cannot accept that keeps the always-required form. Each turn starts with no approved answer. Only a top-level configured tool call observed in that turn can open a candidate. It must be the sole tool call in its assistant message, with no other top-level calls outstanding. Every subsequent top-level tool call invalidates the candidate. Results must match the active current-turn call ID, must not have `is_error` true, and must carry the valid bounded envelope and matching draft digest. Unknown, duplicate, nested, prior-turn, ambiguous, oversized, malformed, failed and superseded results cannot authorize an answer. A later failed validation cannot reuse an earlier success. Accepting a steering request invalidates both pending and approved validation before the new input is injected, withholds authorization while the injection is pending, and invalidates again when it settles or is cancelled; delayed earlier results cannot restore it.
4. In a constrained turn, a DONE candidate must equal the validated result's `text` exactly, including whitespace and Unicode. The published final then carries the additive optional ACI field `Final.text_mode: "verbatim"` (ACI 0.5.23); every other final omits it. Missing or mismatched validation becomes `classified-failure` with the bounded `final-answer-validation` classification and a generic diagnostic, never the unvalidated candidate. No ResultMessage fallback, exhausted iterator, or alternative success emission bypasses this gate. Approval, provider failure, interruption, budget and authentication paths retain their established statuses and precedence. A constrained interruption or timeout retains its status but replaces candidate-derived text with the platform interruption or timeout diagnostic; an IDLE final cannot publish an unvalidated candidate.
5. Bundles with a `finalAnswer` policy emit no provisional `TextDelta` on ACI in any turn, because a later trigger call can constrain a turn whose early text would already have been streamed. History and telemetry retain internal diagnostics. Apply the final validation gate after other status decisions but before successful history persistence or emission. Runner connector notices cannot decorate a verbatim final; an unconstrained answer of the same bundle keeps them.
6. HTTP callers advertise exact-output support with request control header `X-Curie-Final-Answer: 1`. A constrained runner refuses a missing or unsupported version before accepting the event or starting the model. Its successful event response carries the same header only when the bundle declares a policy; unsupported response values are refused by new callers. The worker binds this flag to that response's TurnStream, never sandbox-global mutable state. It renders a DONE answer literally, without receipt or inferred-repository text, only when that negotiated flag is set and the final carries `text_mode: "verbatim"`; other answers of the same runner keep ordinary rendering. A verbatim final on a response that did not negotiate exact output fails closed with the `final-answer-validation` classification. Action records remain unchanged. Failure and approval messages retain their separate rendering paths. The existing durable answer outbox stores the already validated, undecorated reply and replays it unchanged. The CLI advertises the same support and preserves terminal text. In-process skill evaluation has no worker decoration and retains the same runner publication gate.
7. Extend the owned channel reply contract with reply wire 1.2 and an optional `text_mode: "verbatim"` on text-only `ReplyUpdate`. Only this new form uses 1.2; absent fields keep the exact existing 1.0/1.1 serialization and validation. A verbatim answer carries a delivery ID, no structured message, progress, settlement or navigation payload, and the original validated text. The completion outbox persists this mode with the answer in a new version-isolated `answer-completion-v2` hash and `answer-v2` pending index family. Older readers of legacy and answer-v1 indexes never sample it. New readers fairly drain all supported families, retain namespace identity through every lease/generation check, clear, failure, retention and health operation, and preserve the existing shared terminal marker. An unsupported reply version must not abort unrelated legacy sweep work. Constrained DONE producers use it; ordinary failure, interruption and approval producers retain their existing forms. Adapters must refuse unsupported versions instead of interpreting them as the legacy form.
8. Verbatim adapters preserve the logical text. The Slack adapter bypasses the `curie-reply` parser, Markdown conversion and navigation rendering, emits literal plain-text blocks, and partitions oversized text without adding code-fence scaffolding. Concatenating the original payload portions reconstructs the approved text exactly. Rejected literal blocks surface as delivery errors; there is no legacy-rendering fallback. Slack's display behavior is outside byte-level platform control and requires live integration qualification. Exactness means validated logical text and lossless transport payloads, not identical visual formatting across channel clients.
9. Older runners reject the unknown sidecar key at startup. Older workers and HTTP clients cannot activate a constrained new runner because they do not advertise exact-output support; new callers remain compatible with unconstrained old runners, which ignore the additive header. A caller asserting support is responsible for preserving the approved text. The separate executor endpoint does not run the configured SDK validation tool and cannot advertise this support. Protected model turns using the SessionRunner gate can deliver the verbatim update directly while preserving reply-ref adoption and witnessed settlement; their fixed completion records keep answer fields absent. This does not qualify durable answer recovery on the protected lane. This is a configured application boundary inside the existing trusted runner, not proof against a malicious runner, validator or caller.

Realizing paths: `aci_protocol.events` (optional `Final.text_mode`), `curie_runner.plugin` (strict sidecar reader), a new `curie_runner.final_answer` module (bounded call/result correlation), `curie_runner.translate` (current-turn observation and provisional suppression), `curie_runner.session` (both terminal publication sites and connector notice), `curie_runner.server` (event admission and response negotiation), `curie_worker.runner_client` (response-bound policy flag), `curie_worker.kernel.attempt` plus `curie_worker.kernel.delivery` (exact DONE rendering), and `cli/src/runner.rs` (exact-output support negotiation), `channel_protocol.reply` (versioned verbatim update), and `curie_worker.slack_sink` plus `curie_worker.slack_text` (literal lossless delivery), and `curie_worker.markers` plus `curie_worker.completion_health` (version-isolated verbatim outbox lifecycle). Tests use independently authored synthetic bundles and SDK-shaped messages only.

## Consequences

- A bundle can require its own validator without platform-specific report semantics or an additional model run.
- Failed validation is terminal; it does not rerun actions or fabricate an approved answer.
- Bundles with a policy lose streaming previews in every turn. Constrained turns also sacrifice automatic textual platform footers and interpreted Markdown/structured-reply rendering for exact publication integrity.
- Tools and model prompts must implement the declared envelope and copy its `text` exactly. A digest binds the observed draft; it is not authentication or semantic proof.
- Result limits reject oversize content instead of truncating it. Other unconstrained answers retain existing delivery bounds and lossless Slack continuation behavior.
- All successful terminal routes, interrupt and timeout overrides, steering freshness, and durable adapter replay need negative tests. Provider-shaped fixtures establish protocol behavior; they do not qualify a real provider or a live Slack deployment.

## Alternatives considered

- Prompt-only validation: does not enforce tool success or text identity.
- Recognize a tool-name suffix or a JSON object in arbitrary history: loses call provenance and freshness.
- Deliver the last successful validation despite later tool activity or failure: can publish a stale answer.
- Rewrite or semantically compare the candidate after validation: makes the platform another validator and can alter approved content.
- Persist render mode only in process memory: restart would replay the answer through the legacy formatter.
- Reuse the legacy channel version with an unrecognized rendering field: strict old adapters would not receive a truthful capability/version declaration.
- Signal approval only through the event response header: the header is fixed before the turn runs, so a workflow-scoped bundle could not tell its caller which answers were approved, and every answer would be rendered literally.
- Let the caller select the workflow: the caller does not know which request the model will treat as analysis, and its selector would become a second, untrusted activation path.
- Activate by inspecting the request text: that is semantic intent detection the platform cannot perform reliably.
