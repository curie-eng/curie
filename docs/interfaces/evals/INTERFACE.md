The scorer slot is now a typed `Scorer` Protocol above the port; the seam overall is still SOFT because the request-in / results-out contracts are wire shapes, not a code interface.

## The black line

The eval seam is defined by two wire contracts, not a code interface: the `curie:evals` Valkey stream schema (request in) and the `EvalMatrix` DTO the API reads back (results out). The scorer/grader slots in *above* the port (a case names a grader; the runner applies it), and the result store (Langfuse) sits *behind* the recorder. Swapping either the grader family or the store means honoring the same stream payload and the same version/suite-tagged trace+score shape; the stream, the recorder's tag convention, and the matrix DTO are the opinionated core.

## Current contract

Request side — one stream field `payload` (`STREAM_PAYLOAD_FIELD`, `packages/aci-protocol/src/aci_protocol/service_config.py::STREAM_PAYLOAD_FIELD`) holding an `EvalJob` JSON, the shared wire model between the API producer and the worker consumer (`packages/aci-protocol/src/aci_protocol/wire.py::EvalJob`, issue #492): `agent_id`, `version_id`, `sha`, `suite`, `bundle_ref`, `target_url`, `model`, `requested_at` (`model` is the model id the suite should be run under, `None` when the caller did not pin one, e.g. the `target_url` shortcut). Consumer group `curie-eval-workers` is created and read by the eval stream consumer (`apps/worker/src/curie_worker/eval/stream.py::EvalStreamConsumer.ensure_group`, `apps/worker/src/curie_worker/eval/stream.py::EvalStreamConsumer._read_loop`).

Case + grader models — `EvalCase` is `{id, input, grader, shared_history, expect_status}` (`apps/worker/src/curie_worker/eval/models.py::EvalCase`), where `shared_history` (default `false`) opts a case out of the per-case fresh-conversation reset and `expect_status` (frozen `ExpectedStatus`, `apps/worker/src/curie_worker/eval/models.py::ExpectedStatus`, default `done`) asserts the turn's terminal session status, so an approval-gated case can assert `awaiting-approval` — the gate holding is a green result; `Grader` is `{kind: GraderKind, expected, case_sensitive}` (`apps/worker/src/curie_worker/eval/models.py::Grader`) where `GraderKind` is the enum-dispatched family `EXACT | CONTAINS | REGEX | TOOL_CALLED` (`apps/worker/src/curie_worker/eval/models.py::GraderKind`), applied by `Grader.grade(output, trajectory)` (`apps/worker/src/curie_worker/eval/models.py::Grader.grade`). The three text matchers grade the turn's final answer text and ignore the trajectory; `tool_called` (ADR-0022 Phase 1) grades the observed tool-call trajectory instead, asserting a named tool actually ran, and reuses `expected` as the tool name so the frozen case schema takes an additive enum value rather than a new field. This is the single "grader family": deny-by-default (a case must name a grader) and fully deterministic, so a run is reproducible; an LLM-judge grader is a later addition governed by ADR-0042 and is not built.

Scorer seam — the pass/fail decision is now a swappable `Scorer` Protocol above the port (`apps/worker/src/curie_worker/eval/scorer.py::Scorer`): `score(case, output, trajectory) -> ScoreResult`. `EvalRunner` captures both the answer text and the tool-call `trajectory` (the ordered `tool` field of each `tool_note` frame) and delegates to an injected scorer, defaulting to `GraderScorer` (the frozen grader over the text — behavior-preserving). The second, tier-1 scorer is `TrajectoryScorer`: a deterministic matcher over the tool-call sequence with modes `EXACT | IN_ORDER | ANY_ORDER | PRECISION | RECALL`, configured above the port via a `case_id -> TrajectorySpec` mapping the run layer supplies (`apps/worker/src/curie_worker/eval/scorer.py::TrajectorySpec`), with a case that has neither a spec nor a `default` failing closed (`apps/worker/src/curie_worker/eval/scorer.py::TrajectoryScorer`). A full expected-*sequence* spec is still not a field on the frozen case: that would change the frozen eval-case schema and stays out of scope. The narrower single-tool assertion is now on the case, as the `tool_called` grader kind above, so the frozen format does carry one trajectory-shaped expectation. `GraderScorer` (`apps/worker/src/curie_worker/eval/scorer.py::GraderScorer`) passes both the answer text and the trajectory straight through to the case's grader. LLM-judge and hosted-eval-API scorers are the later, costlier tiers; they conform to the same Protocol but are not built.

Run-layer sampling — `SampleConfig` (`apps/worker/src/curie_worker/eval/sampling.py::SampleConfig`) wraps the frozen `EvalCase` and scorer without changing either contract. `EvalRunner` (`apps/worker/src/curie_worker/eval/runner.py::EvalRunner`) executes each case `n` times, then `aggregate` (`apps/worker/src/curie_worker/eval/sampling.py::aggregate`) reduces the per-sample results. The default is `n=1`, `policy=majority`, `k=1`; the runner returns that one result unchanged for compatibility. For `n>1`, majority requires a strict majority of graded samples to pass (a tie fails), while `pass@k` passes when at least `effective_k` samples pass, with `effective_k` clamped to `1..n` (`apps/worker/src/curie_worker/eval/sampling.py::SampleConfig.effective_k`). A multi-sample aggregate's `EvalCaseResult` (`apps/worker/src/curie_worker/eval/models.py::EvalCaseResult`) carries `samples` as the draw count, `passes` as the graded pass count, and `policy` as the reduction policy; `variance` is the human-readable reduction summary for graded multi-sample reductions. All-plumbing fake runs remain ungraded rather than becoming a fabricated pass or fail, and may have no `variance`.

Result side — `LangfuseEvalRecorder.record()` (`apps/worker/src/curie_worker/eval/recorder.py::LangfuseEvalRecorder.record`) posts, per case, a trace tagged `["eval", f"version:{run.version}", f"suite:{run.suite}"]` (`apps/worker/src/curie_worker/eval/recorder.py::LangfuseEvalRecorder._trace_event`) plus an `eval_pass` numeric score `1.0/0.0` (`SCORE_NAME`, `apps/worker/src/curie_worker/eval/recorder.py::SCORE_NAME`; `_score_event`, `apps/worker/src/curie_worker/eval/recorder.py::LangfuseEvalRecorder._score_event`). The trace metadata also records the run-layer sampling fields `samples`, `passes`, `policy`, and `variance` from `EvalCaseResult` (`apps/worker/src/curie_worker/eval/recorder.py::LangfuseEvalRecorder._trace_event`), preserving the reduction context in the recorded trace. A *non-graded* row is the exception: when a case's outcome is `PLUMBING_OK` (the fake tier, ADR-0055, `apps/worker/src/curie_worker/eval/models.py::EvalOutcome`) the recorder writes the trace with an extra `plumbing` tag and emits no `eval_pass` score at all (`apps/worker/src/curie_worker/eval/recorder.py::LangfuseEvalRecorder.record`), because `0.0` would read as a fail that never happened and `1.0` is the false green. The same tri-state runs through the models: `EvalCaseResult.passed` is `None` for such a row (`apps/worker/src/curie_worker/eval/models.py::EvalCaseResult.passed`) and `EvalRunResult.summary` keeps it out of the `N/M passed` ratio (`apps/worker/src/curie_worker/eval/models.py::EvalRunResult.summary`). A grid reader must read "trace present, no `eval_pass`" as ungraded, never as missing or failed. The read path is `GET /matrix` returning `EvalMatrix`, querying traces by those tags (`apps/api/src/curie_api/routers/evals.py::eval_matrix`, which calls `list_traces_by_tags(["eval", f"suite:{suite}"])`).

Model dimension (issue #255, BYO-model epic #24) — additive, same convention as `version:`/`suite:`. A run carries the model id it ran under on `EvalRunResult.model`, which the recorder emits as a `model:<name>` tag plus a `metadata.model` field (and a per-case `metadata.cost_usd` when available). `build_matrix` reads them back (`_model_of`/`_cost_of`) into `EvalCell.model` and a per-model `EvalModelSummary` rollup (pass-rate + summed cost) on `EvalMatrix.model_summaries`, so a suite is sliceable by model for pass-rate/cost comparison. Runs with no resolved model (the `target_url` shortcut) record no `model:` tag and fall into the unlabelled column. The console renders the rollup: the wired evals view shows a "By model" pass-rate and cost table whenever the matrix carries `model_summaries` (`apps/ui/src/views/wired/WiredEvals.tsx`). `cost_usd` is real: the runner prices the token counts the ACI `final` event carries against a local per-model table (`apps/worker/src/curie_worker/eval/pricing.py::cost_usd`, issue #390) and stamps the result on each case row (`apps/worker/src/curie_worker/eval/runner.py::EvalRunner`). That table is deny-by-default and list-price-only, so an unpriced model id, a turn that reported no usage, and the fake tier (no real spend) all record `None` and drop out of the cost rollup instead of counting as free. Pricing deliberately sits on the consumer side rather than on the wire: the protocol carries raw usage, what a token costs is the recorder/matrix's concern.

Matrix cell extras — `EvalCell` (`apps/api/src/curie_api/schemas.py::EvalCell`) also carries `detail` (the scorer's optional explanation, distinct from a trace `error`), `stream_id` (the eval-stream entry that produced the cell), `scorer` (`grader` or `trajectory`), and `case_count`. The recorder writes those as trace metadata (`detail`, `stream_id`, `scorer`, `case_count`; `apps/worker/src/curie_worker/eval/recorder.py::LangfuseEvalRecorder._trace_event`) and `build_matrix` reads them back onto the cell. `EvalMatrix.model_version_summaries` (`apps/api/src/curie_api/schemas.py::EvalMatrix`) slices the model rollup per `(version, model)` so a caller can scope completion to one triggered sha rather than the blended window.

Prompt-cache observability (issue #255) — `_GenerationSpan.record_usage` (`runner/src/curie_runner/otel.py::_GenerationSpan.record_usage`) stamps `cache_read_input_tokens`/`cache_creation_input_tokens` on the generation span, so a warm thread's cache reads surface on the trace — the signal a translating gateway silently broke caching.

## Implementations today

Two scorers through the `Scorer` seam — the four-kind deterministic grader family, three text matchers plus `tool_called` (`GraderScorer`, the default), and the deterministic tool-call trajectory matcher (`TrajectoryScorer`, five modes) — and one store (Langfuse, via `LangfuseEvalRecorder`). Both scorers write results through the identical recorder/`EvalRunResult` path. No LLM-judge/hosted scorer and no second store adapter exists yet.

## Known leakage

One gap remains. The eval-case format is now converged and frozen (issue #8, ADR-0019): both the CLI scaffold/loader (`cli/src/evals.rs`) and the worker's `load_suite_from_bundle` (`apps/worker/src/curie_worker/eval/stream.py::load_suite_from_bundle`) build to one schema, `apps/worker/schema/eval-cases.schema.json`, generated from the Pydantic `EvalSuite`/`EvalCase`/`Grader` models (`apps/worker/src/curie_worker/eval/models.py`) and guarded by the same regenerate-and-diff drift gate as the frozen packages. The CLI hand-mirrors the schema in Rust and is kept honest by a byte-level conformance test against the shared committed fixture. "Frozen" means format changes land in one reviewed change across both languages, not that the format never moves: ADR-0022 Phase 1 added the `tool_called` grader kind as a new enum value reusing the existing `expected` field, regenerating `eval-cases.schema.json` and updating the Rust mirror in `cli/src/evals.rs` together. Still open: the `version:`/`suite:` trace-tag convention is an unfrozen string contract hand-aligned between the recorder (`apps/worker/src/curie_worker/eval/recorder.py::LangfuseEvalRecorder._trace_event`) and the matrix reader (`apps/api/src/curie_api/routers/evals.py::eval_matrix`) — a rename on one side silently breaks the grid.

`EvalCase` rejects unknown case keys in both loaders. This catches unsupported
tier labels and spelling errors instead of silently dropping them. `EvalSuite`
and `Grader` remain tolerant because only case keys are closed.
