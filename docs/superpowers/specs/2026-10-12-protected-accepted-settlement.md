# Protected accepted settlement and retained delivery proof

<!-- @spec PROTECTED-HOOK-LANE-6 -->

This contract realizes Accepted ADR 0191 retention and fenced settlement for the protected worker lane. It changes neither frozen ACI/QueuedTurn bytes nor original payload/envelope/source authority or retained accepted-drain evaluation. It defines implementation obligations, not observed runtime qualification.

## One repair and existing seams

Admission gains a permanent checked event index. An injected protected marker wrapper writes original-proof context, owned terminal evidence and the existing done/outbox generation under one delivery fence. The same API enqueue owner releases exactly that accepted quota member after verifying this evidence. A closed capacity adapter separates known derived fields from the two unchanged primary strings. Graveyard inspection never becomes replay.

`apps/worker/src/curie_worker/kernel/core.py::Kernel.__init__` already injects `markers`. `apps/worker/src/curie_worker/markers.py::Markers.settle_fenced` is the actual existing ownership seam: GET lease equals owner AND delivery hash `gen` equals acquired generation, followed by completion hash `record`, `done=1`, `gen`, pending SET membership and done marker. Therefore a `ProtectedMarkers(Markers)` in a new module can override that operation with new private Lua; no core edit is demonstrated necessary. Do not call unchanged `super().settle_fenced()` and then write a bridge in a second call. That gap loses its durable context on crash and its old lease on reclaim.

The integration owner owns core/shared files and actual mediator retirement. This contract does not implement retirement, infer it from a finished ACI stream, or label incomplete cleanup successful. The protected settlement wrapper must receive the mediator's independently verified actual retirement result for the exact event/launch. If actual retirement is incomplete/unavailable, no refundable terminal witness is written; durable owed context may remain staged. The accepted worker must remain unable to start again while that mediator retirement operation is pending. The controlled-launch contract supplies the stop/control fence, not this bridge.

## Names and ownership

Deterministically derive `g = SHA256(canonical([runtime_id,runtime_generation]))`, where UUID and generation are validated by existing record codecs and canonical encoding is the existing ASCII sorted compact JSON convention. Set `P = protected:lane:worker:<g>`, source stream `curie:runs`, group `protected-<g>`, dead stream `P:dead`. A worker instance name may vary; P/group cannot be caller-overridden. Positive composition consistently uses this derivation within the existing private prefix/group constraints. It creates no second runtime generation authority.

| Key | Type and contents | Writer |
| --- | --- | --- |
| `protected:admission:event:<event_id>` | Immutable STRING, closed canonical `{schema_version:1,event_id,intent_digest}` | Existing enqueue/admission owner only |
| Existing `intent:<digest>`, `state:<digest>`, `commit:<digest>`, `binding:<event_id>` under `protected:admission:` | Existing exact records, unchanged bytes/meaning | Existing enqueue owner only |
| `protected:admission:quota` | Existing ZSET, member is original delivery digest | Existing enqueue owner only |
| `P:settlement:<event_id>` | Immutable terminal witness STRING defined below | Protected fenced marker wrapper |
| `P:completion-context:<event_id>:<completion_gen>` | Immutable STRING containing closed proof references and exact original CompletionRecord JSON bytes | Protected marker wrapper |
| `P:completion-repair:pending` | SET of event IDs, bounded sampled recovery index | Protected wrapper |
| `P:completion-resolution:<event_id>:<completion_gen>` | Immutable STRING `{schema_version:1,event_id,completion_generation,resolution}`; resolution exactly `emitted` or `graveyard` | Protected wrapper, after confirmed emit / successful bounded graveyard XADD |
| `P:done:<event_id>`, `P:completion:<event_id>`, `P:completions:pending` | Existing marker STRING / HASH `record,done,gen,cause` / SET | ProtectedMarkers, existing key builders |
| `P:lease:<stream>:<group>:<entry_id>`, `P:delivery:<stream>:<group>:<entry_id>` | Existing delivery fence keys, unchanged | Existing DeliveryLeaseStore |
| `P:capacity_wait:record:<event_id>` and existing capacity indexes | Existing durable wait format | Existing wait store via protected adapter |

There is no TTL on event index, binding, intent, commit, settlement or owed completion context. Original state remains as today. Refund does not delete any proof. Resolution can remove its own completion context and outbox after confirmed delivery, retaining settlement and original proofs. No reclamation policy is added. The completion context contains completion JSON, not a second full queued payload or secret. Existing durable capacity storage remains the owner of its original `fields` dictionary.

Worker adds GET-only access to `protected:admission:event:*`; it keeps only GET on original intent/state/commit/binding and existing immutable control reads. No worker SET/DEL/TTL/ZREM on admission/control/source; in particular `ZREM protected:admission:quota` stays broker-denied. Enqueue adds its own event-index write selector and a narrowly scoped **read-only** selector for `P:settlement:*`, `P:completion-context:*`, `P:completion-resolution:*` plus needed outbox HGET/HMGET and repair SISMEMBER. Bind these selectors to the provisioned runtime P rather than broad lane write authority. Enqueue EVAL selectors must include those read patterns without giving them SET/DEL/HSET/SREM. Use the existing AuthenticatedEnqueueClient credential; no new application issuer, generic broker client, API endpoint or worker completion credential is introduced.

For Lua key declarations, measure the exact pinned broker selector behavior: a separate `+eval` selector may need key-name visibility for the read-only original-proof families as well as P's writable keys. Give it only the EVAL command and those declared key families; actual script GET uses the read selectors, while script SET/DEL/ZREM on admission/control/source still has no matching command+key selector. Do not solve a declared-key refusal by widening the existing all-command lane selector. The same rule applies to enqueue EVAL visibility of lane witnesses: only read commands match those lane keys. Prove both direct and in-Lua forbidden mutations broker-denied, not merely wrapper-hidden.

## Closed records and original proof lookup

Terminal witness exact fields:

`schema_version=1, event_id, intent_digest, manifest_digest, runtime_id, runtime_generation, broker_run_id, envelope_sha256, payload_sha256, committed_stream_id, delivery_stream, delivery_group, delivery_entry_id, delivery_owner, delivery_generation, completion_generation, completion_record_sha256, completion_context_sha256, marker_value, retirement_ref, retirement_proof_sha256`.

Generation fields use the existing canonical bounded generation rules; completion generation is the wrapper-minted UUID hex used by the existing outbox; marker is existing `1` or `history_capacity`. Retirement reference/digest refer to the mediator's actual verified receipt/owned registry result, never worker-authored successful-cleanup evidence. The delivery entry may be a capacity copy; committed stream ID always comes from the original intent/receipt. Owner is an internal fence token and is never logged. Closed canonical witness/context maximum is 64 KiB; original proof reads keep current 16 KiB caps and queued payload keeps current 262144-byte cap.

Completion context exact fields:

`schema_version=1, event_id, intent_digest, manifest_digest, runtime_id, runtime_generation, broker_run_id, envelope_sha256, payload_sha256, committed_stream_id, completion_generation, completion_record_json`.

`completion_record_json` preserves the exact JSON string passed to the marker operation. Strictly validate it as existing CompletionRecord, including matching event IDs, existing TurnCompleted and the already-resolved route; its digest is included in the witness. The terminal witness is the owner evidence; context by itself is merely staged data and grants no completion/dispatch/refund authority. Context contains enough to reconstruct precisely this owed outbox generation after a partial write, without rebuilding a route or inventing a payload. Restore the immutable envelope directly from binding through event index, original intent and exact commit. Cold proof restoration does not set Dispatchable or authorize a model.

New admission extends the existing checked Lua transaction with event-index STRING type precheck and NX/collision validation before final immutable commit. Its value must match event ID and digest derived from DeliveryIdentity; repeat with identical bytes is idempotent, differing bytes fail closed. Index written without commit is not acceptance. Recovery establishes the same checked index before commit; failure retains index and existing retained records as non-accepted proof. Existing committed admissions lacking an index are backfilled only by the admission owner from a bounded quota census or one caller-known identity, validating original intent/binding/receipt first. A fallback worker census, if needed for unreleased legacy parked members, stays current limit-plus-one <=64 and cannot justify refund without owner backfill. Never SCAN historical intents or reconstruct unknown refunded identities.

Worker finder normally performs one event-index GET and the referenced intent/state/commit/binding GETs. Require closed index, digest(identity)==index digest, exact event match, envelope digest, all original immutable tuple comparisons and exact original receipt as `_commit_verdict` currently does. Quota membership is neither discovery nor acceptance proof. Original index/intent/commit remain discoverable after refund, independently of new members consuming capacity. Preserve `_retained_authority` q/r logic and live broker run_id checks unchanged for execution; completion restoration has its own explicit no-execution operation and also refuses a replacement/unreadable broker epoch.

## Fenced settlement, crash recovery and egress

`ProtectedMarkers.settle_fenced` has the existing signature. Its caller must supply verified original delivery scope, exact lease triple/token/gen and the mediator's actual retirement result. The wrapper revalidates original proof and passes exact raw snapshots into one new Lua operation. Validate closed fields, expected runtime-derived P/group, bounded record bytes, key types and every snapshot **before the first write**. Recheck live INFO run_id, current lease token and delivery hash `gen`. For a first terminal write also require exact PEL consumer ownership for that entry and no contradictory existing settlement/outbox/context/resolution.

Write order after guards:

1. SADD event to repair pending; SET NX exact completion context. An interrupted prefix without terminal witness authorizes nothing.
2. SET NX exact immutable terminal witness. At this instant durable owed JSON and a recovery index already exist. No model may subsequently start this event, even if the normal done marker expires or has not yet been written.
3. Perform the existing fenced outbox write with precisely the witness completion gen (`record`, `done=1`, `gen`, cleared `cause`), SADD existing outbox pending and set normal done marker with existing TTL/marker semantics. No admission mutation or XACK occurs here.

A same-generation identical replay returns the existing generation and may repair its own absent outbox. Conflicting terminal/context/outbox gen never overwrites. An already terminal event cannot be resettled by a later lease owner. Marker-only/leaseless/publish-successor methods fail closed in ProtectedMarkers; this lane requires a reply handle and enables no cron successor/background publication. Ordinary Markers behavior remains unchanged.

Redis Lua errors can preserve command prefixes. If interrupted after witness but before normal outbox/done/ACK/refund, the durable context plus repair index reconstructs **the same** outbox gen by snapshot CAS, without a live lease or new run. The immutable witness is the terminal authority; repair is not new terminal authority. Kill after successful EVAL before the caller receives its answer must converge identically. There is no permitted inter-call crash gap between existing fenced terminal and bridge: both are realized by this one override. A preexisting bare done/outbox lacking protected witness/context is held for owner investigation, never retroactively declared owned settlement from done=1 alone.

Override `is_terminal` to check valid immutable protected settlement before existing marker/outbox facts. Verify original proof before treating a row as the protected event; missing/malformed proof parks. Existing outbox `done=1` remains useful dedupe evidence while pending, but cannot create a refundable witness. Expired done marker, cleared outbox, ACK, absent lease, capacity state and Refused verdict never permit a rerun of a witnessed terminal event.

The guarded kernel facade owns a protected bounded completion sweep rather than forwarding the ordinary sweep's age-discard branch (`apps/worker/src/curie_worker/kernel/completion.py` currently clears aged pending payloads). At startup and maintenance: sample <=64 repair/pending members with a bounded wall-time budget; restore per-generation context+original proof; compare witness/context/outbox record/gen; emit only done owed records via the already-resolved route. Missing proof leaves them owed and private. It must not borrow a live handler ContextVar for cold recovery. A protected reply sink verifies the same context for the kernel's live completion call. Neither age nor done TTL discards protected owed proof.

On confirmed emit, `clear_completion(event_id,generation)` checks exact terminal/outbox gen and restored context before writing NX emitted resolution, then clearing only that generation's outbox/context and pending/repair membership. The wrapper must distinguish this confirmed-send call from an administrative discard; the protected facade does not invoke discard. A crash after actual send before durable emitted resolution may duplicate the completion, consistent with existing at-least-once egress. A crash after resolution before clearing is repaired without reemitting. Generation mismatch touches nothing. On a DeletedReplyTargetError, XADD the existing bounded completion graveyard row first, then write exact-generation `graveyard` resolution and clear its outbox/context; partial failure keeps either owed evidence or its retained diagnostic. Other egress failures leave the context/outbox owed. Settlement/original proof survives either resolution.

## Admission-owner accepted refund

Add a closed `release_accepted(identity)` facade method, not a worker callback and not generic ZREM. API's existing budgeted reconciler iterates the same at-most-64 quota members (with overflow failure, never silently incomplete census). For committed members it establishes checked event index if necessary and invokes this operation. Preparing recovery stays unchanged. No additional full-history sweep.

Owner reads bounded original index/intent/state/commit/binding plus derived runtime P's exact settlement and either (a) owed context+repair membership, or (b) immutable exact-generation emitted/graveyard resolution. Strict parsing verifies original receipt/reserved stream ID, immutable tuple and binding digest; witness event/digest/P/group/broker epoch; record/context digest and exact completion generation. It does not require outbox emission: durable terminal **and durable owed completion** suffice. A staged context alone, commit alone, parking ACK, exhausted-cap diagnostic, refusal or missing lease does not suffice. Outbox still pending is not a reason to retain consumed execution capacity.

One owner-only Lua refund compares the exact bytes of every validated original proof/witness/context-or-resolution snapshot and repair membership used in that decision, validates key types/live run_id, then executes only `ZREM protected:admission:quota <original_digest>`. Retained context can race a confirmed emit: torn snapshots return retry, then reread the emitted resolution; never waive evidence. Return `released` if one member removed and `already_released` on zero only after the same original terminal proof still validates. A lost response is safe to repeat. No SET to state/commit, no deletion/TTL, no second accepted event or second runtime binding. Concurrent enqueue can reuse capacity without hiding the old intent.

## Closed copy adapter and graveyard observer

Primary verification still accepts exactly `payload` and `protected_envelope`, with their original UTF-8 strings unchanged. Do not loosen `verify_delivery` to ignore arbitrary extra keys. A new protected capacity adapter recognizes only the actual constants from `capacity_wait.py`: `curie_capacity_wait_generation` (required for a wake), optional `curie_capacity_wait_reply_ref`, optional `curie_capacity_wait_terminal_only='1'`, plus optional actual telemetry `traceparent`. Use existing canonicalize_traceparent, never a new tracing authority.

Before projecting the two primary fields, read this event's exact wait hash in derived P and compare stored `fields` primary strings byte-for-byte. Require canonical positive bounded generation equal to hash `generation`, current copied entry ID equal to `wake_entry`, expected stream/group, and admissible state (`woken` on first wake; `active` only on same owned wake recovery). Supplied reply_ref must equal stored nonempty `reply_ref`; absence must agree with absence. terminal_only presence/value must match stored terminal_only and existing recognized cause (`capacity_wait_expired`, `delivery_exhausted`, `grant_unknown`). Trace metadata must be valid and remains diagnostic only. All extra fields, missing wait proof, copied metadata on a primary row, changed primary strings or mixed wait generations refuse/park; none grants settlement. Revalidate wait snapshot at its existing begin_grant/confirm_grant lease+generation fences. A wait deadline or unknown grant is not itself proof of terminal ownership or stopped execution.

Preserve `Dispatchable.source_fields` as the two original primary strings. Separately carry validated derived wait metadata in an internal adapter object for actual Consumer wait handling; never rewrite QueuedTurn/envelope or pass a projection that silently loses its generation. Capacity park/grant/wakeup continues using existing stores and delivery fences; permanent terminal witness prevents a wake from launching a finished event. If existing capacity Lua tests only done/outbox and both are gone, guarded facade checks permanent settlement before scheduling/grant; marker wrapper may repair its normal marker, but the runner guard must independently refuse permanent terminal evidence immediately before every positive start.

Existing delivery graveyard adds exactly `dl_original_id`, `dl_delivery_count`, `dl_reason`, `dl_dead_lettered_at`, escaping original `dl_*` names. A bounded observer of `P:dead` can recover the two primary strings and validate only these known diagnostic fields plus the closed capacity copy form if present. Completion graveyard rows are distinguished by existing `event_id,completion,dl_source='completion-outbox'` shape, with original proof resolved through permanent event index. Observation has no group, dispatch, refund, ACK, replay, requeue, or automatic terminal interpretation. Graveyard is bounded best-effort evidence; settlement/index are the durable proof and cannot depend on graveyard survival.

## RED tests and minimum implementation ownership

Write failing source integration tests first against real isolated protected Valkey; fake external endpoints only. No tests are executed by this contract. Required cases:

1. Event index: collision/type/partial-before-commit/missing original proof; owner-only writes; bounded legacy backfill; after refund exact original lookup still succeeds while another admission uses freed capacity. Worker quota ZREM, admission/control/source mutation denied by broker.
2. Fenced wrapper: actual Kernel calls injected ProtectedMarkers; wrong lease/token/gen/PEL consumer/stream/group/event/retirement result does not write; identical replay preserves exact gen. Inject prefix failures and process kill after terminal durability/before outbox/done/ACK/refund or response. Fresh process repairs same completion, original model counter stays one. No fabricated cleanup or successful retirement while mediator stop/deletion is incomplete.
3. Cold completion: no handler context; pending outbox older than normal done TTL; delete/expire done marker while outbox done=1; completion still restores/verifies/emits once per attempted delivery and never authorizes model. Confirmed-clear race, lost emit response, stale generation and proof outage retain correct owed context. Expired ordinary retention age does not discard protected owed proof. Resolution-prefix crash repairs no reemit. Invalid legacy bare outbox never yields refund.
4. Refund: commit/staged context/ACK/lease expiry/refusal/capacity wait/graveyard alone retain quota; durable exact terminal+owed context refunds once before emission; lost refund response/concurrent reconcilers converge; torn clear/refund snapshots retry; wrong digest cannot release another member. Original immutable bytes stay unchanged and no TTL is added.
5. Capacity: actual park/wake/terminal wake retains both primary strings; valid current metadata passes projection and reaches real wait handling; unknown fields/stale gen/false reply ref/wrong wake ID/terminal flag/cause and invalid trace reject. Compatible closed-admission q/r drain remains accepted; new broker epoch refuses model. Permanent terminal witness prevents wake/reclaim/flag-clean retry after done expiry.
6. Graveyard: actual cap path keeps XADD-before-XACK, bounded MAXLEN, positive-idle/live-owner fences; observer does not consume/replay/refund/start. Diagnostic-only or evicted rows cannot erase durable settlement/proof.

Disjoint implementation tasks under this contract:

* Package/API owner: event codec/index, atomic admission extension/backfill and constant-size worker finder; refund codec/Lua, enqueue read-only selectors and reconciler extension. These touch shared admission files and stay one owner/sequential.
* Worker retention owner: new protected marker/settlement Lua/context/sink/bounded sweep modules and RED crash tests; inject through existing constructor. No `markers.py`, kernel/, consumer.py or threadlock.py changes.
* Integration composition/copy owner: new closed capacity/graveyard adapter, narrow guarded facade wiring, derived P/group configuration, verified mediator retirement input and actual positive-composition tests. Integration owner retains shared files; no other agent edits them.

Before positive activation, the integration owner verifies the final combined candidate and required full local suites. This contract establishes a concrete source dependency, not a passing check, qualified runtime, preventive deployment boundary, actual stop proof, or production activation.
